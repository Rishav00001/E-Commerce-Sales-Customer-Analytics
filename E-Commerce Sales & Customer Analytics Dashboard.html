Key findings (full dataset, 2014–2017)

Strong growth, healthy marginSales $2.30M, profit $286K (12.5% margin). Sales grew +29.5% in 2016 and +20.4% in 2017 after a flat 2015 (−2.8%).
Discounts above 20% destroy profitOrders with 0% discount earn a 29.5% margin and 10–20% earn 11.6%. Above 20% every band is loss-making; the 50%+ band loses $76.6K on only $64K of sales (856 order lines).
Furniture sells but barely earnsFurniture is 32% of sales but only $18.5K profit (2.5% margin) vs Technology $145K and Office Supplies $122K.
Three sub-categories lose moneyTables −$17.7K, Bookcases −$3.5K, Supplies −$1.2K. Tables lose money even though their average discount is 26%.
301 of 1,850 products are unprofitableThe worst: Cubify CubeX 3D Printer (−$8.9K), Lexmark MX611dhe printer (−$4.6K), Chromcraft conference tables.
GeographyWest and East drive 70% of profit. Central region margin is only 7.9%. Texas (−$25.7K), Ohio (−$17.0K) and Pennsylvania (−$15.6K) are the biggest loss-making states.

Data-driven recommendations

  1. Cap discounts at 20%. Add an approval rule for anything above it. Orders discounted above 20% lost about $135K in total, which is nearly half of total profit.
  2. Reprice or phase out Tables and Bookcases. Renegotiate supplier cost or raise list price; stop deep-discount promotions on these.
  3. Review the worst 20–30 SKUs (e.g. 3D printers, certain laser printers, conference tables) for delisting or minimum-margin pricing.
  4. Investigate Texas, Ohio and Pennsylvania. Likely heavy discounting plus high shipping/fulfilment cost; compare discount rate to profitable states.
  5. Double down on high-margin lines such as Copiers (37% margin), Paper (43%), Accessories (25%) with bundles and cross-sell.
  6. Protect growth in 2018: focus acquisition on the Consumer and Corporate segments in West/East where margin is strongest.

Note: discount and loss findings show association from observed data, not proven causation; a good caveat to mention in the interview.

Build this in Power BI Desktop (about 60–90 minutes)

This page is a working preview of the dashboard. A .pbix file can only be created inside Power BI Desktop, so follow these steps and use the ready-made DAX below to rebuild it with the same CSV.

Step 1 · Load the data

  1. Home → Get data → Text/CSV → select Sample - Superstore.csv.
  2. Set File Origin to 1252: Western European (Windows). The file is not UTF-8, so the default makes some characters look broken.
  3. Click Transform Data.

Step 2 · Clean in Power Query

  1. Set Order Date and Ship Date to Date type (use Using Locale → English (United States) because the format is m/d/yyyy).
  2. Set Sales, Profit to Decimal, Discount to Decimal, Quantity to Whole number, and Postal Code to Text.
  3. Remove the Row ID column (not needed) and check for duplicates. This dataset has no nulls.
  4. Close & Apply. Rename the table Superstore.

Step 3 · Date table & relationship

Modeling → New table:

Date =
ADDCOLUMNS (
    CALENDAR ( DATE ( 2014, 1, 1 ), DATE ( 2017, 12, 31 ) ),
    "Year", YEAR ( [Date] ),
    "Month No", MONTH ( [Date] ),
    "Month", FORMAT ( [Date], "MMM" ),
    "Year-Month", FORMAT ( [Date], "YYYY-MM" )
)

Select the Date table → Mark as date table (column Date). In Model view, drag Date[Date] onto Superstore[Order Date] (one-to-many). Sort Month by Month No.

Step 4 · KPI measures

Create a separate empty table called _Measures (Enter data) and put every measure there.

Total Revenue = SUM ( Superstore[Sales] )

Total Profit = SUM ( Superstore[Profit] )

Profit Margin % = DIVIDE ( [Total Profit], [Total Revenue] )

Total Orders = DISTINCTCOUNT ( Superstore[Order ID] )

Total Customers = DISTINCTCOUNT ( Superstore[Customer ID] )

Avg Order Value = DIVIDE ( [Total Revenue], [Total Orders] )

Avg Discount % = AVERAGE ( Superstore[Discount] )

Revenue LY =
CALCULATE ( [Total Revenue], SAMEPERIODLASTYEAR ( 'Date'[Date] ) )

Sales Growth % =
DIVIDE ( [Total Revenue] - [Revenue LY], [Revenue LY] )

Profit LY =
CALCULATE ( [Total Profit], SAMEPERIODLASTYEAR ( 'Date'[Date] ) )

Profit Growth % =
DIVIDE ( [Total Profit] - [Profit LY], [Profit LY] )

Step 5 · Discount & low-profit analysis

Add a calculated column on the Superstore table:

Discount Band =
SWITCH (
    TRUE (),
    Superstore[Discount] = 0, "0%",
    Superstore[Discount] <= 0.1, "1-10%",
    Superstore[Discount] <= 0.2, "11-20%",
    Superstore[Discount] <= 0.3, "21-30%",
    Superstore[Discount] <= 0.4, "31-40%",
    Superstore[Discount] <= 0.5, "41-50%",
    "50%+"
)

Sort Discount Band with a helper column (0 to 6), then add these measures:

Loss-Making Lines =
CALCULATE ( COUNTROWS ( Superstore ), Superstore[Profit] < 0 )

Loss Amount =
CALCULATE ( SUM ( Superstore[Profit] ), Superstore[Profit] < 0 )

Is Low Profit Product =
IF ( [Total Profit] < 0, "Loss", IF ( [Profit Margin %] < 0.05, "Low margin", "Healthy" ) )

Profit Rank (Product) =
RANKX ( ALL ( Superstore[Product Name] ), [Total Profit], , ASC )

Step 6 · Page layout

  • Top row: 6 Card visuals: Total Revenue, Total Profit, Profit Margin %, Total Orders, Avg Order Value, Sales Growth %. Use conditional colour on Sales Growth % (green positive, red negative).
  • Slicers: Year (Date[Year]), Region, Category, Segment.
  • Line chart: Date[Year-Month] on X; Total Revenue and Total Profit on Y.
  • Clustered bar: Sub-Category vs Total Profit (conditional formatting: negative = red).
  • Column chart: Discount Band vs Profit Margin % (the key story).
  • Filled map or bar: State vs Total Profit.
  • Table: Product Name, Total Revenue, Total Profit, Avg Discount % with a Top N filter (bottom 10 by Total Profit).
  • Donut: Segment share of revenue.

Finish with a consistent theme, titles that state the insight (e.g. “Discounts above 20% turn orders loss-making”) and a second page called Recommendations.

Step 7 · Publish

Save as Superstore_Dashboard.pbix, take screenshots for your portfolio, and (if you have a work/school account) Publish to Power BI Service for a shareable link. Put the .pbix and screenshots on GitHub.

How to present this project

30-second pitch

“I analysed four years of retail sales data (about 10,000 order lines) in Power BI. I built KPIs for revenue, profit, orders, average order value and growth, then dug into profitability. I found that discounts above 20% make orders loss-making, and that three sub-categories (Tables, Bookcases, Supplies) lose money. My recommendation was to cap discounts and reprice those lines.”

Numbers to remember

  • Revenue $2.30M · Profit $286K · Margin 12.5% · 5,009 orders · 793 customers · AOV ≈ $459
  • Growth: 2015 −2.8%, 2016 +29.5%, 2017 +20.4%
  • Margin by discount: 0% → 29.5%, 11–20% → 11.6%, above 20% → negative, 50%+ → −119%
  • Loss sub-categories: Tables −$17.7K, Bookcases −$3.5K, Supplies −$1.2K
  • 301 of 1,850 products are loss-making

Likely interview questions

  • Why DISTINCTCOUNT for orders? The data is at order-line level; one order has several lines, so COUNTROWS would overcount.
  • How did you calculate growth? A proper Date table marked as the date table plus SAMEPERIODLASTYEAR; a DIVIDE to avoid divide-by-zero.
  • Why a separate Date table? Time-intelligence functions need a continuous date column; it also lets you slice by year/month cleanly.
  • Is discount really the cause of the losses? It is strongly associated. I’d note that cost, product mix and shipping also matter, and suggest an A/B pricing test before changing policy.
  • What would you do next? Customer cohort and RFM analysis, shipping-cost impact, a forecasting page.
  • Data issues? File encoding was Windows-1252, dates in m/d/yyyy, no nulls or duplicates found.
